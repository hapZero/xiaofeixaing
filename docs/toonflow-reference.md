# Toonflow 片段工作台与画布参考结论

核对基线（2026-07-22）：`HBAI-Ltd/Toonflow-app` 提交 `bc61ec7a1b5df31293b286981a5f4ad4635464ee`，独立前端仓库 `HBAI-Ltd/Toonflow-web` 提交 `9c4cb0ec7d4f6b4067c7768e2df8cdc7f8587214`。

## 商用许可边界

Toonflow 的 `LICENSE` 以 Apache-2.0 为基础，但文件末尾附加了商业条款：将软件或衍生版本作为产品提供给两个及以上独立第三方使用前，需要取得 HBAI-Ltd 的书面商业授权，并且不能移除 Toonflow 标识或版权信息。

因此小飞象只采用可独立验证的产品模式和交互规律，不直接复制 Toonflow 源码、视觉标识或提示词。若未来决定直接引入其代码，必须先完成商业授权与 NOTICE 合规审查。

## 结论

Toonflow 值得参考的是成熟的生产组织和画布交互，不是直接复制它的数据实现或前端源码。

公开前端源码中仍保留了没有接通业务的 `genText()`、`generateVideo()`、`handleBatchDownload()` 以及示例轨道初始化；因此“页面看上去成熟”不能直接等同于“公开代码可以作为小飞象的功能底座”。小飞象只吸收已经由前后端共同证明的交互规律，所有按钮继续连接自己的真实 API、持久任务与版本表。

小飞象现有 `Episode → Segment → Shot → SegmentVersion` 数据模型与 Toonflow 的 `Script → VideoTrack → Storyboard → Video candidates` 基本同构：

- 小飞象的 `Segment` 对应 Toonflow 的 `VideoTrack`，是创作者实际生成、重做和选择版本的单位。
- 小飞象的 `Shot` 对应 Toonflow 的 `Storyboard`，承载画面描述、动作、时长和资产引用。
- 小飞象的 `SegmentVersion` 对应 Toonflow 一个 Track 下的候选 `Video`，需要显式展示并允许选为当前版本。

因此不增加一套 Track 数据表。小飞象要重做的是片段工作台的表达方式，以及自由画布的交互底座。

## 片段工作台采用的结构

片段页面改成一个完整生产单元，而不是把能力散落在多个卡片和按钮中：

1. 片段头部：片段编号、总时长、镜头数、生产状态、当前版本。
2. 参考素材托盘：角色形态、场景、道具、首帧、参考视频、音频和文本引用；明确哪些来自项目资产，哪些来自当前镜头。
3. 生成设置：当前生产方案、底层模型/工作流、生成模式、画幅、分辨率、声音策略和目标时长。创作者默认只看摘要，高级配置可展开。
4. 片段导演指令：像 Toonflow 的 VideoTrack Prompt 一样属于整个片段。默认由片段内全部镜头合成，也允许人工编辑并持久保存；后续生成和重做必须使用同一份可见指令。
5. 镜头轨道：横向展示片段内所有镜头、首帧、时长、状态和单镜修复入口。
6. 结果区：当前视频大预览，旁边展示全部候选版本；重做产生新候选，用户明确“设为当前版本”。
7. 批量操作：批量生成首帧、生成待生产片段、重试失败任务；每项仍进入小飞象持久任务系统。

本轮已把分集下的片段列表升级为生产轨道：每个片段同步显示完成镜头数、候选版本数、当前采用版本、时长和真实运行状态；当前分镜的首帧与视频生成入口直接放在镜头轨道旁，不再隐藏在多层折叠项中。

Toonflow 的成熟点不在“按钮更多”，而在于同一个 Track 中同时呈现参考素材、整段提示词、分镜顺序和多个视频候选。小飞象按自己的领域模型实现同一规律：`Segment` 是创作者的生产单位，`Shot` 是片段内部镜头，`SegmentVersion` 是每次生成得到的候选版本。

页面采用一体化四区布局：顶部参考素材与生成摘要，左侧片段导演指令，右侧当前视频与候选版本，底部连续镜头轨道。模型、工作流、声音路线等底层参数默认收起，只有需要诊断时才展开。

片段仍支持两种内部执行方式：整段多分镜生成，或逐镜生成后合成。前台不要求用户逐个运行 ComfyUI 工作流。

参考素材采用“两层真相”：默认模式读取各分镜从剧本推导出的引用；创作者调整后，保存为片段级显式引用，并覆盖本片段所有分镜的生成输入。切换角色形态、场景或道具后，旧候选版本继续保留，但当前首帧和成片指针失效，避免使用旧画面伪装成新输入的生成结果。整段生成、逐镜首帧、图生视频和单镜修复必须共享同一份有效引用。

## 画布采用的结构

Toonflow 前端源码确认使用 Vue Flow 和 Dagre。小飞象是 React 技术栈，对应采用 `@xyflow/react` 负责拖拽、缩放、连线、框选、小地图和视口，采用 `@dagrejs/dagre` 计算有向生产图布局，不再手写固定列坐标。

当前小飞象实际上已经接入 `@xyflow/react` 和 Dagre，所以问题不在于缺少画布库，而在于节点内容、交互反馈和生产对象联动还不够成熟。无需更换技术栈，重点补齐以下行为：

- 节点端口、合法连接提示和连线后的真实业务关系写入。
- 节点内部直接显示资产缩略图、片段镜头数、任务进度、失败原因和当前版本。
- 深层缩放时保持清晰的信息层级，支持一键自动布局、适应视图和最小地图。
- 右侧检查器只编辑当前节点，生成操作进入持久任务，关闭画布后仍可恢复。
- 固定生产主链与自由创作节点分层：主链用于看全局进度，自由节点用于组合角色、场景、素材和片段，不能混成一批装饰卡片。
- 主链固定显示 `01 剧本 → 02 资产 → 03 分镜 → 04 成片`，自动布局后展示完整方向；阶段节点支持双击进入真实业务页面。

画布节点不是无约束装饰卡片，而是有业务语义的生产对象：

- 故事/剧本
- 角色资产组与角色形态
- 场景和道具
- 分镜表/片段
- 素材上传与图像处理
- 片段视频结果
- 分集与导出

连线必须是有方向、有类型、可校验的输入输出关系。例如角色/场景/道具可以连接到片段，片段可以连接到视频结果；视频结果不能反向成为角色资产。连接后的关系写入现有项目资产引用，不建立第二份业务真相。

画布只保存视图层数据：节点位置、尺寸、折叠状态、分组、视口和边的显示属性。角色、场景、片段、镜头、版本和任务仍以规范化业务表为权威数据。

## 不采用的实现

- 不把整份生产状态同时保存为一个巨大 `flowData` JSON；这会与结构化数据产生漂移。
- 不在一次 HTTP 请求返回后继续用进程内 Promise 跑视频长任务；所有生成继续走可恢复的持久任务。
- 不使用“生成中/成功”等任意字符串作为跨模块状态；继续使用集中状态和错误码。
- 不使用时间戳充当业务 ID。
- 不复制 Toonflow-web 前端源码；技术栈不同，而且其附加商业条款要求提前处理授权。

## 改造边界

第一步替换自由画布底座并保持现有画布 API 兼容；第二步把当前分镜编辑器重排为片段工作台；第三步补充“选择当前片段版本”和批量任务接口。生成、对象存储、版本、质量检查、声音和导出的既有后端能力不推倒重写。

## 单镜修复与版本语义

单个分镜修复完成后，不直接把旧片段继续标记为当前成片：

- 保留旧片段候选及其版本历史，用户仍可预览或恢复。
- 只清除被修改分镜的过期结果；其他已完成分镜继续可复用。
- 当前片段进入“待重新合成”，下一次执行只补齐缺失分镜，再产生新的片段候选。
- 片段当前结果失效时，同步使分集当前成片失效，避免导出混用了旧片段的成片。
- 打开片段页面不会因为“尚无当前视频”自动提交昂贵生成；只有确实中断在生产阶段的持久任务才进入恢复流程。
